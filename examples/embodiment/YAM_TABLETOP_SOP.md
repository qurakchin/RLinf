# YAM 桌面整理数采 SOP

## 两组任务

左右统一以 **top 相机画面** 为准，使用固定、未镜像的画面。白碗始终在左侧无痕贴处，粉碗始终在右侧无痕贴处。粉色勺子对应粉碗，白色勺子对应白碗。

| 组别 | 左袋 | 右袋 | 初始左侧勺子 | 初始右侧勺子 | 保留目标 |
|---|---|---|---|---|---|
| A（入口 1） | 百事可乐 | 可口可乐 | 粉色 | 白色 | 90 条 |
| B（入口 2） | 可口可乐 | 百事可乐 | 粉色 | 白色 | 90 条 |

“初始左/右侧勺子”指录制前放在左/右碗后方的勺子，**不是勺子的最终目标**。两组最终都要求白勺入白碗、粉勺入粉碗。两组英文任务分别指定各自入袋规则；初始勺子均为左粉右白。每组按累计保留编号安排：001–030 百事在左、031–060 百事在中、061–090 百事在右，各 30 条；位置由数采员摆放和登记，脚本不识别瓶子位置。

## 每条录制前

1. 在未录制状态复位场景。白碗、粉碗的底部中心分别对准对应无痕贴；袋子固定不移动，袋口保持可投放状态。若贴品牌标签，标签应随本组入袋规则切换，不能与终端任务相反。
2. 按本组左右颜色摆放两把勺子，在碗后方保持横向并被碗遮挡。勺柄可朝左或朝右；组内不交换勺子的左右颜色，两组均保持左粉右白。使用同一摆放参考图，避免有的样本无需移碗就能取勺。
3. 三个瓶子均放在指定桌布竖线附近，瓶身横向，可改变排列顺序及瓶口朝向；两种品牌都要出现。建议同一轮先固定品牌数量，并在采集记录中注明是“1 百事 + 2 可口”还是“2 百事 + 1 可口”。三个瓶子都必须入袋。
4. 检查 top、left、right 三视角正常，物体可见；确认终端组号、袋子规则和勺子初始位置，再按手柄录制键开始。正常遥操同步沿用原手柄同步按钮。

## 录制、结束和保留

录制中完成品牌分拣和勺碗整理：移动碗露出勺子，同色勺放入同色碗，两只碗最后回到各自无痕贴位置。先分瓶还是先整理碗勺不作硬性要求。

结束前确认：

- 三个瓶子全部落在正确品牌的袋内，已松爪，没有挂在袋口或掉到桌面。
- 白勺的勺头在白碗内，粉勺的勺头在粉碗内，稳定放置；勺柄可以搭在碗沿，与参考结束图一致。
- 白碗回左侧、粉碗回右侧，碗底中心对准原标记。采集前保存一张正确初始摆放的 top 参考图，用于对照碗归位；不要在录制结束前人工移动场景来“修好”结果。
- 松开物体、夹爪退出遮挡后，让最终状态在三视角中清楚可见，再按手柄录制键结束。

终端进入 `[待选择]`：**左脚删除，右脚保存，此阶段中间不用**。错袋、错碗、漏物体、未归位、人工入镜代替机器人完成等不合格轨迹，左脚删除后复位重采。暂计 2/90 删除后回到 1/90；下一条重新计入。等待选择和未录制状态下的场景复位不录入新数据。

右脚后显示保存选择，数据保存和视频导出在后台继续执行，不再提示保存完成、视频导出开始或完成。导出期间可继续录下一条，视频到输出目录查看；导出失败仍会报错。不要把终端暂计进度当作已完成落盘数量。

## 中间踏板返回数采初始位

当前 YAM Box 已启用：中间踏板为 KEY_B（48），初始位已由操作者于 2026-09-09 摆位确认，并完成待录制及录制中回位验证。更换初始位前需重新测量并确认。
初始位保存在公共采集配置的 `env.eval.override_cfg.reset`，
两组入口共用：`enabled: true`、`mode: manual`，`left_qpos/right_qpos` 各为
6 个绝对关节角和 1 个夹爪值。`leader_intervention.foot_switch_reset_key` 填实测键值。
初始关节目标取自黄色键同步后确认的主臂姿态；从臂使用相同目标，保持原本主从绝对映射。
这是保存姿态，不改电机编码器零点，也不会在启动或每条结束时自动运动。

1. 启动后按黄色键开启跟随，踩中间踏板，看到 `[复位完成]` 后按白键开始录制。
2. 完成任务、松开物体后踩中间踏板，主从四臂平滑回位；**回位过程仍录入本条数据**。
3. 看到 `[复位完成]` 后按白键结束，再左脚删除或右脚保存。

回位中重踩中间踏板不会重启运动，白键暂不切换录制；黄色键中止回位并关闭跟随，
从臂保持当前姿态，主臂恢复原重力补偿，录制状态不变。回位完成也恢复原主臂增益。
主臂捏合扳机是被动结构，不能自动归位；夹爪全程仍跟随手柄，不因回位自动松开。
首次启用需空手、低速检查整段回位路径，避开桌面、物体和人手；关节插值不包含碰撞规划。

## 启动与输出

先进入目录并激活环境，每次只启动一个采集进程：

```bash
cd /home/yambox/cynws/RLinf
source .venv/bin/activate
```

按本次组别选择以下一条命令执行：

```bash
bash examples/embodiment/collect_tabletop_cleanup_1.sh
bash examples/embodiment/collect_tabletop_cleanup_2.sh
```

每次默认新建 `logs/tabletop_cleanup/variant_N/时间/`，每次启动默认目标为 90 条，不会自动汇总同组历史会话。如果上次已经保留并验收 20 条，另起会话补 70 条：

```bash
bash examples/embodiment/collect_tabletop_cleanup_1.sh runner.num_data_episodes=70
```

不要同时运行两条命令。达到目标后等待程序正常完成后台保存和视频收尾，再启动下一组。

在本次输出目录内：

每条保留回合使用独立 `id_N` 分片，分片内部从 `episode_000000` 编号。
上一条的 Parquet 封装和 MP4 导出在后台继续，新回合写入新的分片；
不要只凭文件名 `episode_000000` 判断是同一条数据，应连同 `id_N` 查看。

- 原始数据：`collected_data/rank_0/id_N/data/chunk-000/episode_XXXXXX.parquet`。
- 英文任务：对应分片 `meta/tasks.jsonl`，由启动入口写入，不能两组都误用旧的 `pick_block` 或旧勺碗映射。
- 验收视频：`collected_data/rank_0/review_videos/id_N/episode_XXXXXX/{top,left,right}.mp4`。
- 运行日志：`run_embodiment.log`。

每组最终统计 90 条实际已保存、视觉验收合格的轨迹，共 180 条；失败和删除尝试不计入。记录各会话路径、保留数及事后剔除数。首条先检查英文任务和三视角视频，确认本组映射正确后继续批量采集。历史已采数据的任务文本不会被这些脚本自动修改。
